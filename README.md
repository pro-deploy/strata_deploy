# Развёртывание сервера нейросети на движке Strata

Этот документ описывает, как развернуть движок Strata с программным интерфейсом (API), совместимым с OpenAI, на удалённом сервере с видеокартами NVIDIA. Развёртывание выполняет интерактивный скрипт `deploy.sh` из этого репозитория. Он запускается на вашем компьютере, подключается к серверу по SSH (Secure Shell, защищённый протокол удалённого доступа), загружает туда комплект установки из каталога `strata-2xa10` вместе с исходным кодом движка из каталога `strata` и ставит всё необходимое. Исходный код Strata хранится в этом репозитории и ниоткуда не скачивается, поэтому изменения в чужих репозиториях не ломают развёртывание. Каталог `strata` содержит неизменённый снимок коммита `cbfd5b92` репозитория [Niko1221/Strata](https://github.com/Niko1221/Strata) со своей лицензией `strata/LICENSE`; происхождение снимка записано в `strata-2xa10/strata-source.env`. В `strata/third_party/llama.cpp` лежат исходники llama.cpp того коммита, который закрепил Strata (`3cf0325`), распакованные так же, как это делает его программа установки, поэтому она их не скачивает. Из интернета при установке берутся только CUDA Toolkit из репозитория NVIDIA, пакеты Python из PyPI и сама модель с Hugging Face.

Пошаговая инструкция с иллюстрациями для сотрудников без опыта администрирования (аренда сервера с видеокартами в Intelion Cloud, развёртывание из веб-терминала или PowerShell, выбор числа видеокарт, расходы и остановка сервера) приведена в [docs/intelion/Strata-Intelion-instrukciya.pdf](docs/intelion/Strata-Intelion-instrukciya.pdf). Исходный текст инструкции и сборщик PDF лежат в каталоге `docs/intelion`.

## Модели

Скрипт предлагает на выбор одну из двух моделей.

Первая модель, Qwen3.6-35B-A3B в варианте UD-Q4_K_XL от Unsloth, содержит 35 млрд параметров, из которых на каждый токен работают около 3 млрд. Скачивание занимает около 23 ГБ.

Вторая модель, Qwen3.8-Flash-Next в варианте IQ3_XXS (сжатие GSQ-RCO от ISTA-DASLab), содержит 125 млрд параметров. Скачивание занимает около 76 ГБ. Её эксперты хранятся в оперативной памяти сервера, а в видеокарте находится остальная часть модели и наиболее нужные эксперты.

В API модели доступны под постоянными именами `qwen3.6-35b-a3b` и `qwen3.8-flash-next`; именно их нужно указывать в поле `model` клиента. Имена с вариантом сжатия (`qwen3.6-35b-a3b-ud-q4_k_xl` и `qwen3.8-flash-next-iq3_xxs`) тоже принимаются. Запрос с другим именем модели сервер отклоняет.

Обе модели запускаются одинаково: на каждой видеокарте работает своя копия модели (реплика), а единый API распределяет запросы между репликами. Каждая реплика обрабатывает до четырёх запросов одновременно. Параметр распределения `replica_load_tokens` равен 20000: при значении по умолчанию 3000 агенты с общим длинным системным промптом скапливались на одной реплике. Это установлено замерами Flash-Next на трёх A10. Контекст выбирает сама программа установки Strata по объёму памяти видеокарты. Чтение изображений включено: визуальный кодировщик (mmproj, ~0,9 ГБ) скачивается с закреплённой ревизией и работает на видеокарте при её объёме от 23,5 ГиБ, а на меньших картах (A10 показывает 22,5 ГиБ) — на процессоре, несколько секунд на изображение; память видеокарты при этом остаётся экспертам модели.

## Что потребуется

Компьютер, с которого запускается развёртывание, должен работать под macOS или Linux. На нём нужны программы `ssh`, `tar` и `curl`, а также `git`, если репозиторий получен клонированием (по нему записывается номер коммита комплекта). Для входа по паролю нужен OpenSSH версии 8.4 или новее; если версия старее, установите программу `sshpass` (на macOS: `brew install hudochenkov/sshpass/sshpass`).

Сервер должен работать под Linux на архитектуре x86_64 с systemd, иметь драйвер NVIDIA (команда `nvidia-smi` должна отвечать) и доступ в интернет к репозиторию NVIDIA (CUDA Toolkit), PyPI (пакеты Python) и Hugging Face (модель). Python 3.10 или новее с модулем venv скрипт при необходимости ставит сам через apt-get. Готового движка для этой версии Strata в выпусках на GitHub нет, поэтому программа установки компилирует движок на сервере под его видеокарты: при первой установке она подключает репозиторий NVIDIA и ставит через apt CUDA Toolkit (несколько гигабайт), а затем собирает движок за 10-20 минут. При повторной установке собранный движок используется повторно. Вход выполняется под пользователем root либо под пользователем с правом sudo без пароля.

Ориентировочные требования к памяти на сервере с двумя видеокартами по 24 ГБ такие. Для Qwen3.6-35B-A3B нужно около 64 ГиБ оперативной памяти и около 55 ГиБ свободного места в `/opt` (с учётом CUDA Toolkit и сборки движка). Для Qwen3.8-Flash-Next нужно около 96 ГиБ оперативной памяти (по замерам на A10 каждая реплика закрепляет около 40 ГБ под экспертов) и около 180 ГиБ свободного места в `/opt`, потому что кроме скачанных файлов программа установки готовит из них пакет для движка. Если памяти или места меньше, скрипт предупредит и спросит, продолжать ли.

## Запуск

Получите репозиторий и запустите скрипт:

```bash
git clone --branch v1.0.0 https://github.com/pro-deploy/strata_deploy.git
```

Здесь `v1.0.0` обозначает выпущенную версию комплекта; список версий приведён на странице [Releases](https://github.com/pro-deploy/strata_deploy/releases). Без параметра `--branch` загружается текущее состояние ветки `main`, которое может отличаться от выпущенной версии.

```bash
bash strata_deploy/deploy.sh
```

Скрипт задаёт вопросы по порядку: адрес сервера, порт SSH, пользователь, пароль (вход всегда выполняется по паролю, и пароль нигде не сохраняется), модель (1 или 2) и порт API. Значение в квадратных скобках подставляется, если просто нажать Enter, а ответы предыдущего запуска (кроме пароля) запоминаются в файле `~/.config/strata-deploy/last.env` и предлагаются по умолчанию. Если ответ имеет неверный формат, вопрос повторяется с пояснением.

Перед установкой скрипт проверяет сервер: архитектуру, видеокарты и драйвер, оперативную память, свободное место и уже работающие службы нейросетей. Затем он показывает сводку и ждёт подтверждения. Отдельные вопросы появляются только при реальной необходимости: если на сервере работают другие службы нейросетей (например, прежняя служба vLLM), которые займут те же видеокарты и поэтому будут остановлены, либо если оперативной памяти или места на диске меньше ориентировочной нормы.

## Ход установки

После подтверждения комплект и архив исходного кода Strata из каталога `strata` загружаются на сервер в каталог `/root/strata-kit`, и установка запускается там в фоне, поэтому обрыв SSH её не прерывает. Исходный код распаковывается в `/opt/strata`, модели скачиваются в `/opt/strata-data`. Программа установки Strata (`setup.sh`) запускается без вопросов: она создаёт окружение Python, ставит CUDA Toolkit и компилирует движок, скачивает модель с закреплённой ревизией, проверяет размер и SHA-256 каждого файла и записывает конфигурацию запуска. Затем скрипт включает реплики по одной на видеокарту, создаёт службу systemd `strata.service` с автозапуском и запускает её. Первая установка занимает от 20 минут до часа в зависимости от скорости скачивания. При повторной установке окружение, движок, модель и API-ключ используются повторно.

Пока движок загружает модель в оперативную память и видеокарты, порт API на сервере закрыт. В это время вместо журнала показывается индикатор загрузки: прошедшее время, полосы заполнения памяти видеокарт и оперативной памяти и последняя строка журнала службы, например:

```text
  ⠼ 2:41  видеокарты ████████░░░░░░░░ 22,1/44,9 ГиБ  память ██████░░░░░░░░░░ 51,3/125,7 ГиБ  loading experts
```

Обычно загрузка занимает от 3 до 15 минут. Если модель не ответит за 30 минут или служба остановится с ошибкой, скрипт покажет последние строки журнала и завершится с сообщением об ошибке. Нажатие Ctrl+C прерывает только показ, установка на сервере продолжится, а журнал можно посмотреть командой `ssh -p ПОРТ root@АДРЕС tail -f /root/strata-kit/install.log`.

## Проверка и API-ключ

В конце скрипт обращается к API снаружи и проверяет две вещи: что модель отвечает с ключом (HTTP 200) и что запрос без ключа отклоняется с кодом HTTP 401. Если снаружи API недоступен, откройте порт API в межсетевом экране сервера или облачного провайдера. API-ключ хранится на сервере в файле `/root/strata-api.key` и в конфигурации запуска `/opt/strata/strata-<модель>.json` с правами доступа только для root. По умолчанию скрипт показывает ключ в терминале: достаточно нажать Enter на последнем вопросе.

Адрес API имеет вид `http://АДРЕС:ПОРТ/v1`. Ключ передаётся в заголовке `Authorization: Bearer КЛЮЧ`. Проверить работу можно так:

```bash
curl -H "Authorization: Bearer КЛЮЧ" http://АДРЕС:18080/v1/models
```

## Версии

Комплект выпускается версиями по семантическому версионированию: номер текущей версии записан в файле `VERSION`, а коммит, из которого она собрана, помечен git-тегом `vX.Y.Z` с тем же номером. Сценарий показывает версию в начале работы и в сводке, а также записывает её в `/opt/strata/deploy-info` строкой `version=`. Каждое изменение комплекта, которое выкатывается на серверы, получает новую версию: номер в `VERSION` увеличивается, изменения фиксируются коммитом, и на этот коммит ставится новый тег; уже выпущенный тег никогда не переносится. Чтобы обновить развёрнутый сервер до новой версии, выполните на сервере `git -C strata_deploy fetch --tags`, затем `git -C strata_deploy checkout vX.Y.Z` и снова запустите `bash strata_deploy/deploy.sh`.

Версия движка определяется содержимым каталога `strata` в этом репозитории. Чтобы перейти на другую версию, замените содержимое каталога файлами нужного коммита Strata, исправьте `STRATA_COMMIT` в `strata-2xa10/strata-source.env`, зафиксируйте изменения коммитом и запустите скрипт снова. Каждое развёртывание записывает файл `/opt/strata/deploy-info` со временем развёртывания, происхождением снимка Strata, коммитом этого репозитория, моделью и числом реплик. По этому файлу видно, какой именно код сейчас работает на сервере. Если в `deploy.sh`, в каталоге `strata-2xa10` или в каталоге `strata` есть незафиксированные изменения, к номеру коммита комплекта добавляется пометка `-dirty`; если репозиторий получен архивом без git, вместо номера записывается `unknown`.

## Управление службой

Служба называется `strata`. Состояние, перезапуск и журнал службы доступны стандартными командами systemd на сервере:

```bash
systemctl status strata
```

```bash
systemctl restart strata
```

```bash
journalctl -u strata -f
```

Журналы каждой реплики движка лежат рядом с конфигурацией в `/opt/strata` (файлы `strata-<модель>.r0.log`, `strata-<модель>.r1.log` и так далее). Обновления пакетов Ubuntu не перезапускают службу автоматически (файл `90-strata.conf` для needrestart), поэтому после обновления системных библиотек службу нужно перезапустить вручную в удобное время.
