# Развёртывание сервера нейросети на движке Strata

Этот документ описывает, как развернуть движок Strata с программным интерфейсом (API), совместимым с OpenAI, на удалённом сервере с видеокартами NVIDIA. Развёртывание выполняет интерактивный скрипт `deploy.sh` из этого репозитория. Он запускается на вашем компьютере, подключается к серверу по SSH (Secure Shell, защищённый протокол удалённого доступа), загружает туда комплект установки из каталога `strata-2xa10` и ставит всё необходимое. Исходный код движка сервер скачивает из публичного репозитория [Niko1221/Strata](https://github.com/Niko1221/Strata) по коммиту, закреплённому в файле `strata-2xa10/strata-source.env`.

## Модели

Скрипт предлагает на выбор одну из двух моделей.

Первая модель, Qwen3.6-35B-A3B в варианте UD-Q4_K_XL от Unsloth, содержит 35 млрд параметров, из которых на каждый токен работают около 3 млрд. Скачивание занимает около 23 ГБ.

Вторая модель, Qwen3.8-Flash-Next в варианте IQ3_XXS (сжатие GSQ-RCO от ISTA-DASLab), содержит 125 млрд параметров. Скачивание занимает около 76 ГБ. Её эксперты хранятся в оперативной памяти сервера, а в видеокарте находится остальная часть модели и наиболее нужные эксперты.

Обе модели запускаются одинаково: на каждой видеокарте работает своя копия модели (реплика), а единый API распределяет запросы между репликами. Каждая реплика обрабатывает до четырёх запросов одновременно. Параметр распределения `replica_load_tokens` равен 20000: при значении по умолчанию 3000 агенты с общим длинным системным промптом скапливались на одной реплике. Это установлено замерами Flash-Next на трёх A10. Контекст выбирает сама программа установки Strata по объёму памяти видеокарты. Обработка изображений отключена.

## Что потребуется

Компьютер, с которого запускается развёртывание, должен работать под macOS или Linux. На нём нужны программы `ssh`, `tar` и `curl`, а также `git`, если репозиторий получен клонированием (по нему записывается номер коммита комплекта). Для входа по паролю нужен OpenSSH версии 8.4 или новее; если версия старее, установите программу `sshpass` (на macOS: `brew install hudochenkov/sshpass/sshpass`).

Сервер должен работать под Linux на архитектуре x86_64 с systemd, иметь драйвер NVIDIA (команда `nvidia-smi` должна отвечать) и доступ в интернет к GitHub и Hugging Face. Python 3.10 или новее с модулем venv скрипт при необходимости ставит сам через apt-get. CUDA Toolkit на сервере не нужен: программа установки Strata скачивает готовый движок под видеокарты сервера. Вход выполняется под пользователем root либо под пользователем с правом sudo без пароля.

Ориентировочные требования к памяти на сервере с двумя видеокартами по 24 ГБ такие. Для Qwen3.6-35B-A3B нужно около 64 ГиБ оперативной памяти и около 45 ГиБ свободного места в `/opt`. Для Qwen3.8-Flash-Next нужно около 96 ГиБ оперативной памяти (по замерам на A10 каждая реплика закрепляет около 40 ГБ под экспертов) и около 170 ГиБ свободного места в `/opt`, потому что кроме скачанных файлов программа установки готовит из них пакет для движка. Если памяти или места меньше, скрипт предупредит и спросит, продолжать ли.

## Запуск

Получите репозиторий и запустите скрипт:

```bash
git clone https://github.com/pro-deploy/strata_deploy.git
```

```bash
bash strata_deploy/deploy.sh
```

Скрипт задаёт вопросы по порядку: адрес сервера, порт SSH, пользователь, пароль (вход всегда выполняется по паролю, и пароль нигде не сохраняется), модель (1 или 2) и порт API. Значение в квадратных скобках подставляется, если просто нажать Enter, а ответы предыдущего запуска (кроме пароля) запоминаются в файле `~/.config/strata-deploy/last.env` и предлагаются по умолчанию. Если ответ имеет неверный формат, вопрос повторяется с пояснением.

Перед установкой скрипт проверяет сервер: архитектуру, видеокарты и драйвер, оперативную память, свободное место и уже работающие службы нейросетей. Затем он показывает сводку и ждёт подтверждения. Отдельные вопросы появляются только при реальной необходимости: если на сервере работают другие службы нейросетей (например, прежняя служба vLLM), которые займут те же видеокарты и поэтому будут остановлены, либо если оперативной памяти или места на диске меньше ориентировочной нормы.

## Ход установки

После подтверждения комплект загружается на сервер в каталог `/root/strata-kit`, и установка запускается там в фоне, поэтому обрыв SSH её не прерывает. Сервер скачивает исходный код Strata закреплённого коммита с GitHub и распаковывает его в `/opt/strata`, модели скачиваются в `/opt/strata-data`. Программа установки Strata (`setup.sh`) запускается без вопросов: она создаёт окружение Python, скачивает подписанный готовый движок, скачивает модель с закреплённой ревизией, проверяет размер и SHA-256 каждого файла и записывает конфигурацию запуска. Затем скрипт включает реплики по одной на видеокарту, создаёт службу systemd `strata.service` с автозапуском и запускает её. Первая установка занимает от 20 минут до часа в зависимости от скорости скачивания. При повторной установке окружение, движок, модель и API-ключ используются повторно.

Пока движок загружает модель в оперативную память и видеокарты, порт API на сервере закрыт. В это время вместо журнала показывается индикатор загрузки: прошедшее время, полосы заполнения памяти видеокарт и оперативной памяти и последняя строка журнала службы, например:

```text
  ⠼ 2:41  видеокарты ████████░░░░░░░░ 22,1/44,9 ГиБ  память ██████░░░░░░░░░░ 51,3/125,7 ГиБ  loading experts
```

Обычно загрузка занимает от 3 до 15 минут. Если модель не ответит за 30 минут или служба остановится с ошибкой, скрипт покажет последние строки журнала и завершится с сообщением об ошибке. Нажатие Ctrl+C прерывает только показ, установка на сервере продолжится, а журнал можно посмотреть командой `ssh -p ПОРТ root@АДРЕС tail -f /root/strata-kit/install.log`.

## Проверка и API-ключ

В конце скрипт обращается к API снаружи и проверяет две вещи: что модель отвечает с ключом (HTTP 200) и что запрос без ключа отклоняется с кодом HTTP 401. Если снаружи API недоступен, откройте порт API в межсетевом экране сервера или облачного провайдера. API-ключ хранится на сервере в файле `/root/strata-api.key` и в конфигурации запуска `/opt/strata/strata-<модель>.json` с правами доступа только для root. По умолчанию скрипт показывает ключ в терминале: достаточно нажать Enter на последнем вопросе.

Адрес API имеет вид `http://АДРЕС:ПОРТ/v1`. Ключ передаётся в заголовке `Authorization: Bearer КЛЮЧ`. Проверить работу можно так:

```bash
curl -H "Authorization: Bearer КЛЮЧ" http://АДРЕС:18080/v1/models
```

## Версии

Версия движка задаётся файлом `strata-2xa10/strata-source.env`: в нём указаны репозиторий Strata и полный SHA коммита. Чтобы развернуть другую версию движка, измените `STRATA_COMMIT`, зафиксируйте изменение коммитом и запустите скрипт снова. Каждое развёртывание записывает файл `/opt/strata/deploy-info` со временем развёртывания, коммитом Strata, коммитом этого репозитория, моделью и числом реплик. По этому файлу видно, какой именно код сейчас работает на сервере. Если в `deploy.sh` или в каталоге `strata-2xa10` есть незафиксированные изменения, к номеру коммита комплекта добавляется пометка `-dirty`; если репозиторий получен архивом без git, вместо номера записывается `unknown`.

## Управление службой

Служба называется `strata`. Состояние, перезапуск и журнал службы доступны стандартными командами systemd на сервере:

```bash
systemctl status strata
```

```bash
systemctl restart strata
```

```bash
journalctl -u strata -f
```

Журналы каждой реплики движка лежат рядом с конфигурацией в `/opt/strata` (файлы `strata-<модель>.r0.log`, `strata-<модель>.r1.log` и так далее). Обновления пакетов Ubuntu не перезапускают службу автоматически (файл `90-strata.conf` для needrestart), поэтому после обновления системных библиотек службу нужно перезапустить вручную в удобное время.
